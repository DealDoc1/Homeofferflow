## Implemented and locally checked

- Property listing now starts with preparing a listing agreement; the existing
  planning workspace remains a secondary choice. A saved sale workspace can
  supply its property address and one/two seller names to the interview.
- Six steps cover parties/property, negotiated terms, marketing, seller
  representations, the related-document checklist and review/signing choice.
  Optional detail sections stay collapsed. Compensation is not preselected.
- Dynamic street/mailing address controls retain the application's existing
  semantic Google address detection and lazy Places registration. The isolated
  fixture blocks external requests, so actual Google suggestions were not
  exercised in this browser pass.
- Source wording informed the unrepresented-buyer additional-compensation
  question and relocation/employer-benefits label. Do not describe a related
  document checkbox as a completed or attached document.
- Explicit pre-1978 and HOA-request answers survive save/reopen. Known
  pre-1978 construction selects checklist item C; an explicit HOA information
  request selects G. The server normalizes the same choices. Unknown age or
  tax status is not inferred. Missing seller disclosure does not stop preparing
  the agreement. This does **not** yet assemble the complete related packet.
- Branch changes remove stale MLS delay/display and unselected fee amounts.
  Zero compensation remains explicit. One/two seller names, Unicode and the
  selected broker/associate signing plan are retained.
- A verified-session GET loads only the owner's unsent TXR-1101 record. Tracked
  provider documents cannot be edited. Delivery bookkeeping is not exposed as
  editable interview answers. Updates use the same ID and saved timestamp.
- Duplicate taps are suppressed while saving. Confirmed later saves update
  that draft. Ambiguous/network/server/conflict results direct the agent to
  saved documents, rather than automatically repeating a create.
- The queue uses the friendly name “Sale listing agreement,” exposes Edit
  answers only for unsent/untracked drafts, and focuses the selected agreement
  after refresh. Preview, recipient confirmation and tracked delivery remain
  in the existing flow. No signing order or brokerage-seat gate is added.
- Account changes clear the listing dialog/private queue/send dialog. Late
  list/answer/save/PDF responses cannot populate the next account; late PDF
  bodies cannot open or download after an actor/epoch change. Existing viewer
  paths still work for the current actor.
- The new public JS/CSS assets are registered with the shell asset list. The
  shell version remains the current production v105 at this local checkpoint;
  bump it for the eventual frozen coordinated release, not a docs-only deploy.
